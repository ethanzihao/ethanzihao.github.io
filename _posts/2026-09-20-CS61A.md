# Environment Model

> [!abstract]
> Every expression is evaluated in the context of an environment. 

> [!abstract]
> A name evaluates to the value bound to that name in the earliest(here means the latest one? ) frame in the current environment, in which that name is found. 
## Frame

A frame is a mapping from names to values. **Keep in mind:** One name-value binding is not called a frame, a frame is a sequence of the name-value bindings! 
## Environment

An environment is a sequence(一连串) of frames, such as Global Frame, Local Frame...
## Name Evaluation(计算)

1. Look up the name-value binding from the current frame. 
2. Find the first frame containing the name. 
3. Return the value bound to that name. 
## Function Call

1. Evaluate argument expressions to get argument values (in current environment). 
2. Create a new local frame. 
3. Bind formal parameters to arguments. 
4. Look up the names appeared in the body of the function, back to execute the body, and return the value. 
**Note:** Before a  function is called,  all the parts of the call expression will be evaluated. So you cannot replace a control statement by a function sometimes, since some argument expressions might be invalid. 
**Keep in mind:** When a name is to be bound to a value in a function, python will recognize it as a local variable. You cannot write something like `sum += 1` when `sum` only exists in parent frame, because when you bind `sum` to `sum + 1` , python recognizes the right side `sum` as a local variable. However, obviously `sum` has not been bound to any value yet in the local frame. (you maybe need mutable values, such as lists, or use `nonlocal` )
**Important:** A mutable default argument is dangerous, because every time you call the function, it will be bind to the same value. Here is an example:
```python
def f(s=[]):
	s.append(3)
	return len(s)
"""
>>> f()
1
>>> f()
2
>>> f()
3
"""
```

	1. It is bound to a function in the **current frame**, which is recognized as his **parent frame**, when the function is called and create a new local frame.

## Curry a function

When a function takes two formal parameters like `f(x, y)` , you can curry it , which means to make it a function like `F(f)(x)(y)` . 
```python
"""to curry function f(x, y)"""
def F(f):
	def g(x):
		def h(y):
			return f(x, y)
		return h(y):
	return g
	
"""lambda version"""
F = lambda f: lambda x: lambda y: f(x, y)

>>> max(2, 3)
3
>>> currying = F(max)
>>> currying(2)(3)
3
>>> F(min)(2)(3)
2
```
Steps to curry a function: 
1. Write down the target function, like `f(i, j) ---> F(f)(i)(j)` . 
2. Split the function from left to right. 
3. There is still `(i)` behind `F(f)` , which means the return value of`F(f)` must be a function. 
4. Still `(j)` behind `F(f)(i)` , so it must return another function. 
5. No more formal parameter behind `F(f)(i)(j)` , so the return value must be `f(i, j)` . 
Easy to find out that the whole process is like we **continue to create functions to eat the arguments** that we need into a findable frame, and let the original function `f` work finally.

## Generator

1. A generator is a special kind of iterators. 
2. A generator is returned from a generator function, using `yield` statement. 
```python
def return_a_generator(n):
	for i in range(n):
		yield i

>>> ge = return_a_generator(5)
>>> next(ge)
0
>>> next(ge)
1
```
1. When you call the generator `ge` , the function `return_a_generator` will execute till next yield, and then **paused**. 
2. `yield from` statement will yield each element of a iterator or objects that can be iterated.

## Attribute (属性)

1. An attribute is a name-value pair in the class statement. 
2. Class attribute vs. Instance attribute
	1. class attributes: def: `cla_attr = 114` ; call: both `<instance>.cla_attr` and `<class name>.cla_attr` 
	2. instance attributes: def: `self.ins_attr = 514` ; call: only `<instance>.ins_attr` 
	3. when you type `instance.<attribute_name>` , python always looks for instance attribute first, then class attribute. 
3. A method is a class attribute, whose value is a function. 
4. You can change or create an attribute anytime. 
5. Function `__init__` means to  *initialize* ; the function will be called automatically when a instance is created. 

## Inheritance

```python
class Object_1:
	class_attribute1 = 'aaa'
	def __init__(self, parameter1):
		self.go_bears = parameter1

class Object_2(Object_1)
	def __init__(self, parameter1, parameter2):
		super().__init__(parameter1)
```
For this case
1. Object_2 inherits Object_1, so all the class attributes will be inherited automatically. 
2. About `__init__` 
	1. If Object_2 has no `__init__` , then python will find the nearest `__init__` from its fathers, and call it. 
	2. If Object_2 has its `__init__` , then it will be called. 
		1. If in Object_2's `__init__` is a `super().__init__(...)` , that means it will call Object_2's father's `__init__` as well.(Something like `Object1.__init__(self, parameter1)` )  **Note**: The parameter`self` is returned by `super()` , so you only need to pass others in. 
3. If a attribute is used in a inherited class, and there is a totally same attribute name in his fathers, then python will find from the sons, and go backward until it finds the name, which means you can override a attribute. 
	1. If you want to both modify a function attribute and use its father's attribute, it's expected to use this statements:
```python
"""in Object_2 class statement"""	
	def <a same attribute name in Object_1>(self):
		...
		Object_1.<a same attribute name in Object_1>(self)
		...
```

4. If a name is an function attribute in a class statement, but you bind it to a function somewhere out of the class statement, then python will find it a function and call it if `()` are behind. But you can also call the original attribute by `instance.<attribute_name>(self, )` .

# String Representation

## eval() & exec()

1. `eval(<string>)` is to execute an expression, and return its value. So you cannot write something like `eval('x = 10')` because `x = 10` is an assignment rather not an expression. 
2. `exec(<string of a phrase of a python code>)` , it returns `None` , but can execute a phrase of python code. 
## repr() & str()

1. `str()` returns the content of a string object ( or returns a human-readable value)
2. `repr()` returns the how an object should be present as a python object ( or returns a python-interpretable value)

### Example

For a string `s = 'abc'` , 
1. Its an string object. 
2. Its content is `abc` with no quotation. 
3. If you want to get the content of the string `s` , then you return `abc` , that's what `str()` does. 
4. If you want to clearly present `s` is an string object whose content is `abc` , then you present it as `'abc'`, that's what exactly `repr` does. 
**keep in mind**: Every time you write something like `s = 'abc'`(with quotation), the quotations are telling python that `abc` is a string rather than a name, but the content of the string does not include the quotations, `abc` only. 
### A confusion 

Question: Why when you type `'abc'` in the interactive environment, or REPL , it will print out `'abc'` rather than `abc`  ? 
Answer: REPL will print out `repr(object you typed)` automatically, so `'abc'` is exactly the return value of `repr('abc')` .

# Interface

## What happens when calling `repr()` ?

The behavior of `repr()` is more complicated than just invoking `__repr__` . 
1. Any instance attribute called `__repr__` will be ignored when `repr()` . Only class attributes will be found. 
What `repr()` does is like
```python
def repr(an_object):
	return type(an_object).__repr__(an_object)
```
## Shared messages as interfaces

1. The attribute look-up rules allow different data types to respond to the same message. 
2. A shared message (attribute name) that elicits similar behavior from different object class is a powerful method of data abstraction. 

> [!abstraction] Interface
> An interface is a set of messages, along with a specification of what they mean.
